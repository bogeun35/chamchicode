## 1. 사용자 요구 원문 (시간순)

1. 물고기 소환이 옆에서 뜨기 때문에 좌우만 커버하면 돼. 랜덤으로 그냥 나오도록 해야 해
2. 해상도에 따라서 난이도가 천차만별로 쉬워져. 기본 스케일을 유지하면서 되도록 수정해야 해
3. 물고기의 속도가 너무 비슷해서 난이도가 비슷해
4. 이펙트 등 수석 디자이너 같은 애를 써서 게임성을 더 살려줘
5. 로비·게임 시작·초기화·하드모드 같은 것도 만들어 줘

11. 플레이 시간 99분이 최대로 나오는 것 같아, 버그야

### 2.1 (2026-09-24 ~ 27)
12. 밸런스가 이상해졌어. 처음엔 한 마리도 잡기 힘들고 갈수록 그게 해소되고 숫자가 커지는 재미인데, 지금은 처음부터 도파민이 터지는데
13. 물고기 속도를 높이라는 건 아닌데 물고기가 굉장히 많아 보여. 처음에 1~3원 정도 벌다가 이제 촥촥 올라가는 거였는데. 물고기 종류도 첨부터 많아. 그리고 200원씩 벌려
14. 스킬 쪽은 괜찮은데 도감하고 어종 숙련이 해금되지도 않은 게 먼저 업글되고, 이게 해금 시점의 금액을 반영하지 않으니까 너무 게임이 쉬워. 처음에만 하고 안 보는 거고
15. 전체화면 같은 게 없어서 스크롤되고, 렉이 좀 심해
16. 연출도 1만 원은 크고 1억은 작아. 연출이 이상해. 크리티컬이 더 작고
17. 유물도 확률이 너무 높은 거 아닌가? 후반부에 나올 유물하고 초반부에 나오는 유물을 나눠야 할 것 같은데, 여기도 밸런스 맞춰야 하고. 초반에 유물을 다 올리면 너무 쉬워

### 사용자가 원하는 재미의 기준
- **결핍 → 해소 → 숫자 폭발.** 처음엔 한 마리가 소중하고, 성장하면서 풀리고, 후반엔 숫자가 터진다.
- 기준 감각은 원작 트리 이식(커밋 756fec0) **이전** 판: 시작 멸치 1종, 1~3원, 물고기 적음.
- 연출도 성장 보상이다(초반은 담백하게).
- "물고기 속도를 올려라"가 아니다. 속도는 건드리지 말 것.

## 4. 결정 사항과 이유

| 결정 | 이유 |
|---|---|
| 논리 월드 고정(1280×720 / 720×1280) + 한 배율 | 요구 2·7. 그물·물고기·속도·이펙트가 해상도와 무관하게 같은 비율 |
| 세로 폰 월드 720×1280 | 면적을 가로와 같게. 그 대가로 폰에서 물고기가 작게 보임(최소종 약 24px) — 사용자 판단 보류 중 |
| 하드 마리당 골드 ×1.2 | ×2.6 이면 하드가 일반보다 빨리 깨짐(41분), ×1.6 이면 차이 없음(78분). ×1.2 에서 1.3~1.4배 |
| 숙련 단계 배수 ×1.25 | ×2.2 면 10단계가 서너 어종 뒤로 밀림. 대신 1단계 비용을 해금 시점 경제에 맞춤 |
| 유물 간격을 "뽑힌 유물의 단계" 기준 | 현재 어장 기준이면 난파선 이후 초반 유물도 느려져 초반 6종이 38~48분 걸렸음 |
| 연출 단계(JUICE) | 요구 12. 잡는 양은 2.0 이 이미 원본보다 적었는데 체감이 "처음부터 도파민" — 원인이 첫 판부터 켜진 연출이라 판단 |
| 초반 경험치 숫자 작게·흐리게 | 골드 +1 옆 경험치 +10 이 돈으로 읽혀 "200원씩 벌려" 오해 원인 후보 |
| 획득 숫자 폭 초과 시 표기 단축 | 글씨를 줄이면 1억이 1만보다 작아 보였음(요구 16) |
| 버전 2.1 | 새 기능이 들어간 개편은 둘째 자리, 버그 수정만이면 셋째 자리(2.1.1) |

## 5. 검증하는 법

1. 정적 서버: `node tools/balance/tuna/serve.js 8766 .` (저장소 루트에서)
2. 헤드리스 크롬(원격 디버깅 포트 9224)을 띄우고, `PUPPETEER_CORE` 에 puppeteer-core 경로를 준다.
3. 측정은 **스냅샷으로**: `tuna.html` 을 `tuna-bal-xxx.html` 로 복사해 그걸 잰다(측정 중에도 원본을 고칠 수 있게). 이 이름은 커밋하지 말 것.
4. 여러 판을 동시에 돌릴 땐 `http://127.0.0.2:8766`, `127.0.0.3` … 처럼 **주소를 다르게**(localStorage 가 섞이지 않게).
5. 도구가 비정상 종료하면 크롬에 게임 탭이 남아 5초마다 저장하며 다른 측정을 오염시킨다. `http://localhost:9224/json/list` 로 확인하고 `/json/close/<id>` 로 닫는다.
6. 봇 한 판(클리어까지)은 부하에 따라 실제 1~20분. `protocolTimeout` 은 30분으로 넉넉히 잡아 두었다.

## 6. 작업할 때 주의

- **한 줄 주석 사고**: 이 파일은 한 줄에 코드가 길다. 편집 문자열 끝에 `//` 주석을 붙이면 뒤따르는 코드가 주석 안으로 들어가 조용히 죽는다(2.1 작업 중 세 번 발생 — 물고기 반전 횟수가 NaN 이 되어 초반 규칙이 통째로 안 먹었음). 주석은 `/* */` 로 쓰거나 줄 끝에서만. 편집 후 "바뀐 줄의 `//` 뒤에 코드처럼 보이는 것"을 검사할 것.
- **기존 세이브 호환**: `tuna_save_v3` 키·필드 구조 유지. 새 필드는 `fresh()` 기본값 + 로드 시 합치기로. 선장 id·유물 id·어종 id 를 바꾸지 말 것. 옛 세이브의 숙련·유물 단계는 몰수하지 않는다.
- **다른 세션**: 같은 저장소에서 다른 게임(rock/shell/mine/suika/rhythm/zombie 등)을 여러 세션이 수시로 push 한다. 작업 전 `git fetch` 후 `origin/main` 의 `tuna.html` 과 비교, 커밋은 `tuna.html`(필요하면 `index.html` 의 참치 줄)만.
- **push 전 개인 경로 검사**: PC 경로(`C:\Users\...`)나 테스트 주소가 파일에 들어가지 않았는지 grep.
- 특성 트리 원작값(`TREE_RAW` 비용·효과)은 건드리지 않는 것이 지금까지의 원칙.
