## A. 심사

### A-1. 심사표 (5점 척도, 구현 난이도는 쉬울수록 높은 점수)

| 기준 | 안1 쿵짝항구 대소동 | 안2 쿵짝 참치항 | 안3 둠칫 부두 |
|---|---|---|---|
| 재미·웃음 | 5 | 4 | 4 |
| 신호 명확성 | 4 | 4 | 5 |
| 조작 다양성 | 5 | 5 | 5 |
| 곡 매력 | 4 | 5 | 3 |
| 모바일 적합성 | 4 | 3 | 4 |
| 구현 난이도 | 3 | 2 | 3 |
| 합계 | **25** | 23 | 24 |

- 안1: 실패 흔적이 결과 화면까지 쌓임(셰프 얼굴 참치, 선장 엉덩이 반창고, 전깃줄 갈매기). 다시 할 이유가 가장 분명. 난이도 순서(정박, 따라하기, 길게, 엇박)가 자연스러움. 약점은 복어 떼는 박이 큰북과 동시에 와서 예고가 없음
- 안2: "내 입력이 곡의 빠진 악기" 원칙이 가장 좋음. 약점은 펑크·스윙·스카·뽕짝·하우스 5장르 합성 부담, 스윙 셋잇단 뒷박과 150 BPM 엇박은 폰·블루투스 지연에서 억울함이 큼
- 안3: 시각 큐가 가장 명확(물방울 개수, 칠판 점, 칸 이동). 약점은 3/4 왈츠가 리믹스에서 박자 변환을 요구하고, 본게임 1분 30초~2분으로 길음

### A-2. 결정: 안1을 뼈대로, 안2·안3의 장점을 합침

| 가져온 것 | 출처 | 어디에 | 이유 |
|---|---|---|---|
| 플레이어 입력 = 곡의 빠진 파트 | 안2 | 전 게임 편곡 | 초밥 "척"=백비트 스네어, 넵=합창 윗성부, 빵이=화음 가운데 음, 대파 "칭"=스카 기타. 맞히면 곡이 완성되어 귀로 먼저 앎 |
| 빠른 딱 스냅 | 안2 응용 | 판정음 | 딱 판정이면서 박보다 이르게 누른 경우 성공음을 정확한 박에 예약. 잘 친 사람 귀에 곡이 딱 맞게 들림 |
| 본게임 판정 글자 없음 | 안2 | 본게임 | 캐릭터 반응과 소리로만 알림. 연습에서만 작은 글자 |
| 버릇 한 줄(서두름/늦음) | 안2 | 결과 화면 | 다음 판에 무엇을 고칠지 알려 줌 |
| 속임수는 눌렀을 때만 분모 +1 | 안2 | 점수 | 참은 사람은 손해 없음 |
| 뗄 박 예고: 물방울 개수 | 안3 | 복어 나팔대 | 안1의 약점(큰북이 뗄 박과 동시) 보완. 누르는 순간 물방울 수 = 유지 박 수, 박마다 하나씩 터짐 |
| 박자판 점(흐려졌다 사라짐) | 안2·안3 | 선장님 따라해! | 소리 없이 하는 사람도 콜을 볼 수 있음 |
| 연습 가이드를 한 겹씩 걷기 | 안3 | 전 게임 연습 | 링 있음 → 마지막 단계 링 없음. 본게임 전에 "링 없이도 된다"를 먼저 경험 |
| 헛누름 소량 감점 | 안3 | 점수 | 무작위 연타로 버티기 방지 |
| 완벽 도전에서 아슬 허용 | 안2·안3 | 완벽 도전 | 빗나감·속임수는 1번에 끝, 헛누름은 2번까지 봐줌. 도전이 지나치게 가혹하지 않게 |
| 3번 연속 실패 시 선장이 봐줌 | 안3 응용 | 해금 | 막혀서 그만두지 않게 |
| 첫 실행 박자 맞추기 권유 | 안3 | 타이틀 뒤 1회 | 블루투스 이어폰 사용자 억울함 방지 |
| 박마다 튀는 배경 + 발 구르는 기준 캐릭터 | 안2·안3 | 전 게임 | 박자 기준이 늘 화면에 있음 |
| 빵이 음정이 코드 따라감 | 안2 뱃고동 | 복어 나팔대 | 오래 누른 음이 곡의 화음이 됨 |

뺀 것: 5장르 합성(안2), 3/4 왈츠(안3), 150 BPM(안2), 확률로 뜨는 도전 깃발(안2·안3, 늘 열림으로 단순화), 폭풍우·새벽 모드(범위 밖, 추후 과제)

## 2. 미니게임과 채보

### 2-0. 공통 규칙

**박 표기**
- `마디.박` 예: `5.3` = 5마디 3박, `5.3.5` = 5마디 3박 반(3박과 4박 사이 8분)
- 절대 박(0부터): `beat = (마디-1)*4 + (박-1)`, 초: `t = beat * 60 / BPM`. `t=0`이 1마디 1박
- 전 곡 4/4, 8분음은 곧은 8분(스윙 없음. 셔플 느낌은 하이햇 강약으로만)

**큐와 입력**
- 모든 소리 큐는 같은 시각에 동작 큐가 함께 나옴(소리 0이어도 플레이 가능)
- 큐 → 입력 간격은 게임마다 고정 규칙. 채보는 "큐 시각"만 적고 입력 시각은 규칙으로 계산해도 되지만, 아래 표에는 둘 다 적음
- 무게 w: 기본 1. 영차·아주 긴 음은 2

**연습 공통**
- 반주는 드럼+베이스만. 2마디(따라해는 콜+응답 2마디) 루프를 반복
- 박자 링: 입력 1박 전부터 목표 지점에서 반지름 3배 → 1배로 줄어드는 원. 딱 닫힐 때가 입력 시각
- 단계마다 "아슬 이상" 성공 횟수를 채우면 다음 단계. 마지막 단계는 링 없이
- 한 단계에서 4번 연속 빗나가면 힌트 문구 교체(아래 표의 힌트)
- 연습 판정 글자: 목표 지점 위에 작게 `딱!`/`아슬`/`빗나감` 0.4초
- 연습 끝 → 캐릭터 한마디 + 1마디 쉬고 본게임
- 한 번이라도 연습을 끝낸 게임은 제목 카드에서 `연습 건너뛰기` 표시(키보드 S 또는 카드 아래 버튼)

**곡 "회전초밥 셔플"** (C장조)
- 코드 4마디 반복: C | Am | F | G7 (27~28마디 C)
- 드럼(16분 칸, 0=1박): 킥 0, 8 (짝수 마디에 10 추가) / 하이햇 짝수 칸 전부, 정박 칸(0,4,8,12) 세게, 사이 칸(2,6,10,14) 70% / 가이드 림 4, 12에 25% 볼륨(플레이어 척이 채울 자리)

## 3. 판정·점수·등급·저장

### 3-1. 판정 창 (보정 적용 후 기준, 경계 포함, 계산 오차 1ms 허용)

| 판정 | 탭·누름 | 뗌 | 점수 |
|---|---|---|---|
| 딱 | ±40ms | ±60ms | 1 |
| 아슬 | ±90ms | ±120ms | 0.6 |
| 빗나감 | 포착 창 안이지만 위 범위 밖, 또는 입력 없음 | 위 범위 밖 | 0 |

- 포착 창: 탭·누름 ±150ms. 이 안의 입력은 가장 가까운(|차이| 최소) 미판정 음에 붙음. 창 밖 입력은 헛누름
- 자동 빗나감: 음 시각 +150ms가 지나도 입력이 없으면 빗나감(안 누름)
- 빠른 딱 스냅: 딱이고 음보다 이른 입력이면 성공음을 음 시각에 예약. 그 밖에는 입력 즉시 발음

### 3-2. 헛누름

- 포착 창 밖의 누름: 판정 없음. 참돌이가 허공에 휘두르는 짧은 동작 + 작은 헛손질 소리
- 점수에서 헛누름 1회당 0.5를 뺌. 상한 없음(0.2점·10% 상한이면 8분음표로 계속 두드리기가 다시 만선이 되므로 공략 차단 우선)
- 인트로 구간(첫 음 1박 전까지)과 끝 음 1박 뒤 이후의 누름은 헛누름으로 세지 않음(박자 따라 두드리기 허용)
- 선장님 따라해!: 콜 마디의 삑(±150ms)에 같이 누른 헛누름(메아리)은 1회 0.2, 합계는 총 무게의 20%까지
- 끼룩단 퇴치: 큐 박(갈매기 착지, 두목 깍) ±60ms 헛누름은 빠름 개그(대파 날아감)로 보여 줌
- 끼룩단 퇴치만 헛누름 1회당 1.0을 뺌(모든 음이 엇박 격자 위라 0.5면 '매 박 엇박에 계속 두드리기'가 69점 그럭저럭으로 통과. 1.0이면 51점 다시 출항)
- 결과 화면에 헛누름 수 표시

### 3-3. 속임수

- 하품: 해당 응답 마디 구간 누름 → 속임수 1회. 비둘기: 착지 박 +0.5박 ±150ms 누름 → 속임수 1회
- 속임수는 눌렀을 때만 분모에 무게 1 추가(점수 0). 참으면 영향 없음
- 속임수 누름은 헛누름 감점과 중복으로 치지 않음

### 3-4. 점수와 등급

```
원점수 = (Σ 판정점수×w − a×일반헛누름 − min(0.2×메아리, 0.2×Σw)) / (Σw + 속임수누름수)   // a = 0.5 (끼룩단 퇴치만 1.0), 일반 헛누름 상한 없음, 메아리는 따라해만
점수 = Math.round(max(0, 원점수) × 100)   // 0~100 정수, 등급은 정수로 판단
```

|---|---|---|
| 다시 출항! | 0~59 | "배가 아직 항구를 못 떠났다냥. 한 번 더!" |

### 3-5. 선장 한 줄 평 (결과 화면 2줄)

- 큐 종류별 성공률(아슬 이상 / 전체) 계산. 표본 3개 이상인 종류만
- 잘한 것: 성공률 최고 종류의 칭찬 문구. 아쉬운 것: 성공률 최저 종류 + 경향(평균 차이 < -15ms 이르게, > +15ms 늦게)
- 속임수를 눌렀으면 아쉬운 것은 속임수 문구가 우선
- 모든 종류(표본 3개 이상, 2종류 이상)의 평균 차이가 서로 10ms 안이고 전체가 15ms 넘게 늦거나 빠르면: 특정 종류를 지목하지 않고 "전체적으로 반 박자 늦었다냥" / "전체적으로 서둘렀다냥"
- 한 번도 안 눌렀으면(헛누름·속임수·인트로 누름도 0): "손이 얼었냐옹? 한 번도 안 눌렀다냥" + 게임별 방법 안내 한 줄
- 선장 평이 "전체적으로 반 박자 늦었다냥 / 서둘렀다냥"을 말한 판은 버릇 줄에서 ms 문장을 빼고 고치는 방법만 남김(평균 |차이| > 30ms면 "설정에서 박자 맞추기를 해 보라냥", 아니면 "조금만 당겨/늦춰 누르면 딱이다냥")

## 4. 조작

| 기기 | 버튼 | 일시정지 | 메뉴 이동 |
|---|---|---|---|
| 데스크톱 | Space, Z, X, Enter, 마우스 왼쪽(캔버스 아무 곳) | Esc, P, 오른쪽 위 버튼 | 방향키 + Space/Enter, 마우스 클릭 |

- 두 번째 버튼 없음. 전 게임 한 버튼(X는 Z와 같음, 양손 번갈아 치기용)
- 누름: pointerdown / keydown(e.repeat 무시). 뗌: 눌린 입력(손가락·키)이 모두 떨어지는 순간(pointerup, pointercancel, keyup, blur)
- 탭 게임: 누름마다 입력 1회(두 손가락 번갈아 치기 가능). 길게 게임: 이미 눌린 상태의 추가 누름은 무시, 모든 입력이 떨어져야 뗌
- 🔊 버튼(왼쪽 아래, party-sound.js)과 일시정지 버튼 위의 누름은 게임 입력이 아님(버튼 요소가 이벤트를 받고 캔버스로 가지 않음)
- 연습·본게임 중 폰 세로: 캐릭터와 목표 지점은 화면 위 60% 안, 아래 40%에 옅은 "여기 아무 데나 톡" 안내(연습에서만 글자, 본게임은 빈 바닥)
- 터치 기기(손가락 입력, 또는 pointer:coarse): 키보드 안내를 숨김. 제목 카드 버튼은 `연습 건너뛰기`((S) 없음), 타이틀은 "화면을 톡 눌러 출근!", 가로 폰 연습 하단은 "화면 아무 데나 톡". 키보드를 쓰면 다시 키 안내
- 연습 건너뛰기('그냥 해 볼래?') 버튼: 기본은 일시정지 버튼 왼쪽. 선장 말풍선과 겹치면(가로 폰, 가로 따라해) 일시정지 버튼 아래 오른쪽 끝, 그래도 겹치면 말풍선 바로 아래

## 5. 기술 설계

### 5-1. 파일 구성 (rhythm.html 한 파일)

```
<head> Jua 폰트 링크, 스타일(캔버스 전체화면, touch-action:none, user-select:none, -webkit-touch-callout:none)
<script src="party-sound.js">   // 🔊 버튼과 음량 값만 공유
<script>
  CFG      판정 창, 선행 시간, 색 토큰
  SAVE     load/save (try/catch)
  AU       자체 AudioContext, 버스(master → bgm / sfx), 악기 합성 함수, 노이즈 버퍼
  SONGS    곡별 반주 생성기(마디 → 음 이벤트 목록)
  CHARTS   채보 데이터(아래 형식) → 음 목록 전개
  ENGINE   시계, 스케줄러, 판정, 자동 빗나감, 일시정지
  SCENES   title / menu / card / practice / play / result / calib / pause
  DRAW     캐릭터 함수 + 게임별 장면 그리기 (가로·세로 좌표표)
  INPUT    pointer/key 처리
  API      window.rhythm
</script>
```

### 5-2. 채보 데이터 형식 (권장)

```js
// [마디, 박, 종류, 옵션] — 종류가 입력 시각 규칙을 결정
sushi: { bpm:100, bars:28, song:'sushi', chart:[
  [3,1,'tok'],[3,3,'tok'], ... [9,1,'tt'],[9,3,'tok'], ... [13,2,'yc'] ... ] }
// tok: 입력 +1박 / tt: 큐 b, b+0.5 → 입력 +1, +1.5 / yc: 영 b 차 b+1 → 입력 +2 (w2)
// salute: [콜마디,'P3'] / [콜마디,'Y'] / [콜마디,'YB']  → 응답 마디 입력
// puffer: [마디,박,'S'|'L'|'X']  → 누름·뗌 시각
// gull:   [마디,박,'g'|'boss'|'dove']
// remix:  [마디,박,종류,{zone:'sushi'}] + 전환 [마디,'T',zone] / 블록 [마디,'B',zone]
```
- 전개 결과 `notes[]`: `{id, kind:'tap'|'hold'|'fake', cue, beat, t, w, relBeat?, relT?, win?:[t0,t1], zone?}`
- 큐 소리·동작 이벤트 `cues[]`: `{beat, t, cue, sfx}` (영의 차, 두목 깍, 뗄 박 큰북 등 모두 포함)
- 전개 직후 합계 검사(콘솔 경고): 게임별 타 수·무게가 이 문서 값과 다르면 경고

### 5-3. 오디오 엔진

- 자체 `AudioContext({latencyHint:'interactive'})`. 첫 사용자 입력(타이틀 탭)에서 생성·resume
- 버스: master → bgmBus(반주·큐 소리) / sfxBus(플레이어 성공음·개그음). 곡마다 `songBus`(bgmBus 아래) 새로 만듦(일시정지·중단 시 통째로 끊기 위함)
- 음량: localStorage `party_bgmvol`, `party_sfxvol`을 읽어 bgm/sfx 게인에 반영. `Sound.setBgmVolume`, `Sound.setSfxVolume`을 이 페이지 안에서 감싸(원래 함수 호출 후 우리 게인도 갱신) 🔊 패널 조절이 즉시 반영되게. party-sound.js 파일은 수정하지 않음
- party-sound 반주 끄기: 로드 직후 `Sound.scene('home')` 호출(그 파일의 BGM은 scene이 home이면 안 돎)
- 큐 소리는 반주 버스로 보냄(음악 음량 0이어도 큐는 들려야 하므로 큐 전용 최소 게인: bgm 0일 때 큐는 sfx 음량을 따름)
- 노이즈 버퍼 1.5초 1개 미리 생성해 재사용. 동시 음성 상한 48

### 5-4. 시계와 스케줄러

- 곡 시각 `s` ↔ 오디오 시각: `ctxT = t0 + s`. 시작 시 `t0 = ctx.currentTime + 0.3`
- 스케줄러: `setInterval(tick, 25)` + rAF에서도 tick 호출. `tick()`은 `ctx.currentTime + 0.1` 이전에 시작하는 모든 이벤트(반주 음, 큐 소리, 큰북)를 예약하고 포인터 전진
- 이벤트 목록은 곡 시작 시 전부 생성해 시각순 배열로 보관(반주 생성기가 마디별로 펼침)
- 늦은 예약: 이벤트 시각이 이미 지났으면 30ms 이내는 즉시 재생, 그 이상은 건너뛰고 `lateSchedules++`
- 들리는 시각(화면용): `heard() = outTs.contextTime + (performance.now() − outTs.performanceTime)/1000` (`ctx.getOutputTimestamp()`). 매 프레임 `ctx.currentTime − performance.now()/1000` 대비 차이를 EMA(α 0.1)로 평활, 20ms 넘게 튀는 표본은 버림. 지원 안 되면 `ctx.currentTime − (ctx.outputLatency || ctx.baseLatency || 0.02)`
- 화면 곡 시각 = `heard() − t0`. 모든 애니메이션은 이 값으로 그림(프레임 누적 금지)
- 판정 기준 = 곡 시각. 자동 빗나감 처리는 tick·rAF·advance에서 `heard() − t0` 기준

### 5-5. 입력 → 곡 시각 환산

```
inputSongT = ctxAt(e.timeStamp) − t0 − offsetMs/1000
ctxAt(p) = 평활된 (contextTime − performanceTime/1000) + p/1000
```
- `e.timeStamp`는 performance.now 기준(최신 브라우저). 이벤트 처리 지연(메인 스레드 바쁨)이 판정에 들어가지 않음
- 입력 핸들러는 판정·소리 발음만 즉시 하고, 그림은 다음 프레임에서
- 사용자 오프셋은 입력에만 적용(화면·소리 시각은 그대로)

### 5-6. 보정(박자 맞추기) 화면

1. 선장이 100 BPM으로 발을 구르고 매 박 "쿵" + 화면 테두리 번쩍
2. 4박 카운트인 후 8박 동안 탭. 각 탭을 가장 가까운 박(±300ms)에 대응, 박 하나에 1탭
3. 8개 모이면 최대·최소 1개씩 버리고 평균 → `offset` 후보(±250ms로 제한, 1ms 반올림)
4. 결과: "평균 +45ms 늦게 누르는 편이다냥. 맞춰 뒀다냥." 버튼 `저장` / `다시`. 미세조정 `-5` `+5`
5. 8박 동안 4개 미만이면 "다시 해 보라냥" 자동 재시작
- 진입: 첫 실행 1회 권유(타이틀 뒤 "블루투스 이어폰이면 꼭 해라냥" 예/나중에), 지도 톱니 버튼
- 보정 화면 판정도 같은 입력 환산 사용(오프셋만 0으로 두고 측정)

### 5-7. 화면 전환

```
title ─탭(오디오 잠금 해제)→ [첫 실행: 보정 권유] → menu(항구 지도)
menu ─장소 선택→ card(제목 카드 2초 자동 진행, 탭 넘김, 연습 건너뛰기/완벽 도전 버튼. 버튼이 2개 이상이거나 터치 기기면 자동 진행 없음)
card → practice → play → result
card ─건너뛰기→ play
result ─한 번 더→ play(연습 없이) / ─지도→ menu
menu ─톱니→ calib → menu
어느 장면이든 ─일시정지→ pause → 이어서(1마디 카운트인) / 지도로
```
- 결과 화면은 0.8초 동안 입력을 받지 않음(마지막 탭이 넘어가지 않게). 이후 Space/탭 = 한 번 더, Esc = 지도
- 지도: 가로는 좌우로 넓은 항구(초밥집 좌하, 갑판 좌상, 축제 무대 우상, 생선 좌판 우하, 축제 배 가운데 바다), 세로는 위에서 아래로 5곳. 잠긴 곳은 어둡게 + 자물쇠, 간판에 최고 점수·메달·도장·봐줌 아이콘
- 첫 지도 진입: 선장 말풍선 "첫 출근이다냥, 초밥집부터!"
- 타이틀: 로고가 116 BPM으로 튐(자체 엔진의 짧은 드럼 루프), 5도장이면 참돌이 선장 모자

### 5-8. 일시정지·백그라운드

- 일시정지 조건: `visibilitychange`(hidden), `pagehide`, `blur`(창 전환), iframe이 화면에서 사라짐(IntersectionObserver), Esc/P/버튼
- 처리: 현재 곡 시각 `sp` 기록 → `songBus` 연결 끊고 폐기 → 재생 중인 빵이 소리 정지(누름 상태는 해제, 해당 음의 뗌은 판정하지 않고 보류) → 스케줄 포인터를 `sp` 이후 첫 이벤트로 되돌림 → `ctx.suspend()`
- 재개: `ctx.resume()` → 새 `songBus` → `t0 = ctx.currentTime + 0.1 + 1마디 − sp` (1마디 카운트인을 틱 4번으로 들려줌) → 재예약
- 일시정지 중 보류된 길게 음: 재개 후 누름 없이 시작되므로 그 음은 판정에서 제외(분모에서 뺌)
- 연습·본게임 이외 장면에서는 일시정지 없이 소리만 끔

### 5-9. 논리 월드 렌더

- 기존 게임과 같음: 캔버스 CSS 크기 CW×CH, DPR ≤ 2. `port = CH > CW` → W,H = 720×1280 또는 1280×720. `VS = min(CW/W, CH/H)`, `OX = (CW − W·VS)/2`, `OY = (CH − H·VS)/2`
- 매 프레임: 전체를 현재 장면 배경색으로 채움(레터박스) → `setTransform(DPR·VS, 0, 0, DPR·VS, DPR·OX, DPR·OY)` → 장면 그리기
- 장면마다 가로·세로 좌표표(2절의 배치표)를 두고 회전 시 즉시 전환(게임 진행은 곡 시각 기준이라 끊김 없음)
- 화면 흔들림은 world transform에 더함(최대 8 논리px)

### 5-10. 모바일 대응

- `<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover">`
- 캔버스 `touch-action:none`, body `overscroll-behavior:none`, `contextmenu` 기본 동작 막기, 선택 막기(길게 누르기 게임에서 돋보기·메뉴가 뜨지 않게)
- pointerdown에서 `preventDefault` + `setPointerCapture`(손가락이 움직여도 뗌이 캔버스로 옴)
- Space 키 `preventDefault`(스크롤 방지)
- 폰 성능: 도형 수 장면당 300개 이하, 블러·그라디언트 최소, 60fps 목표

### 5-11. window.rhythm API

| 함수 | 설명 | 반환 |
|---|---|---|
| `games()` | 게임 목록 | `[{id, name, order, bpm, bars, lengthSec, unlocked, best, grade, medal, stamp, mercy}]` id: `sushi`, `salute`, `puffer`, `gull`, `remix` |
| `chart(id)` | 전개된 채보 | `{id, bpm, beatSec, bars, lengthSec, totalWeight, taps, holds, fakes, notes:[...], cues:[...], practice:[{stage, text, need, loop}]}` |
| `start(id, opt)` | 게임 시작. `opt = {practice:false, sim:false, perfect:false, stage:1}`. `id='calib'`이면 보정 | `true` 또는 오류 문자열(잠김 등). 테스트용 `opt.force:true`는 잠김 무시 |
| `clock(mode)` | `'real'` / `'sim'` 전환. 인자 없으면 현재 값 | 모드 문자열 |
| `advance(sec)` | sim 모드에서 곡 시각을 sec만큼 진행. 내부는 1/240초 단위로 대기 입력 처리·자동 빗나감·장면 전환 | `state()` |
| `input(type, phase, at?)` | `type`: `'key'`/`'pointer'`/`'bot'`, `phase`: `'down'`/`'up'`, `at`: 곡 시각(초, 0 = 1마디 1박). sim에서 `at`을 주면 그 시각이 될 때 처리(미리 여러 개 넣어 둘 수 있음). `at`이 없으면 현재 시각. 오프셋은 `at`에도 적용 | `{queued}` 또는 즉시 판정 결과 `{judge, err, noteId}` |
| `state()` | 현재 상태 | `{scene, game, mode, paused, practice, stage, stageNeed, stageDone, songT, bar, beat, held, combo, counts:{perfect, good, miss, fake, stray}, scoreNow, next:[다음 3음], gags:{faceTuna, squash, poke, yawnFail, bandage, fart, wire, leek, dove}, captain:'normal'|'hat'|'shades', lateSchedules}` |
| `result()` | 마지막 결과 | `{game, score, grade:'retry'|'ok'|'best', gradeName, counts, totalWeight, fakePressed, stray, strayPenalty, meanErrMs, meanAbsErrMs, tendency:'early'|'late'|'ok', perKind:{키:{n, hit, meanErr}}, comments:[칭찬, 아쉬움], habit, lines:{grade, game}, traces:{...}, newBest, unlocked:[...], medal, stamp, perfect:{tried, ok, endedAtBeat}, log:[{noteId, phase, err, judge}]}` |
| `offset(ms?)` | 사용자 보정 읽기/설정(저장됨) | 현재 ms |
| `view()` | 화면 정보 | `{W, H, VS, OX, OY, CW, CH, dpr, orientation:'land'|'port', scene}` |
| `reset()` | 세이브 초기화(테스트용) | `true` |
| `skip(scene)` | 테스트용 장면 이동(`'menu'`, `'result'` 등) | `state().scene` |

- sim 모드: 오디오 예약을 하지 않고(소리 없음) 시계만 내부 값으로 진행. 화면은 그대로 그려서 스크린샷 검수 가능
- sim 곡은 `start(id,{sim:true})` 직후 곡 시각 = -0.3초(실시간과 같은 선행). 연습은 sim에서 단계 성공 수를 채우면 자동으로 다음 단계, 끝나면 본게임으로 넘어감
- 봇 예시(검수자가 콘솔에서):

```js
rhythm.reset(); rhythm.start('sushi',{sim:true, force:true});
rhythm.chart('sushi').notes.forEach(n => {
  if (n.kind==='tap') rhythm.input('bot','down', n.t + 0.060);
  if (n.kind==='hold') { rhythm.input('bot','down', n.t+0.060); rhythm.input('bot','up', n.relT+0.060); }
});
rhythm.advance(rhythm.chart('sushi').lengthSec + 2); rhythm.result().score  // 60
```

  `Object.defineProperty(window, 'rhythm', { configurable: true, get: () => { const w = activeGameWin(); return w && w.rhythm; } });`
