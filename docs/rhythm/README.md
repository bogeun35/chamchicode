## 1. 게임 개요

리듬천국 류의 "짧은 리듬 미니게임 + 리믹스" 형식만 참고한 오리지널 게임. 닌텐도 IP(이름, 캐릭터, 곡, 그림)는 쓰지 않는다. 참스코드 세계관(참치 신입 선원, 고양이 선장)을 쓴다.

| id | 이름 | BPM | 조작 | 판정 수 | 신호 → 누름 간격 |
|---|---|---|---|---|---|
| sushi | 초밥 한 점! | 100 | 정박 탭 | 51 | 톡·톡톡 1박, 영차 2박 |
| salute | 선장님 따라해! | 112 | 한 마디 듣고 따라 치기 (하품은 참기) | 48 | 한 마디(4박) 뒤 |
| puffer | 복어 나팔대 | 88 | 길게 누르고 박에 떼기 | 누름 19 + 뗌 19 | 누름 2박 또는 4박, 뗌은 물방울 수 |
| gull | 끼룩단 퇴치 | 128 | 엇박 탭 | 82 | 반 박 |
| remix | 쿵짝항구 대축제 | 116 | 네 게임 섞기 | 95 (채보 87음) | 원래 게임과 같음 |

- 판정 (현재값, `CFG`): 딱 ±65.5ms, 아슬 ±125.5ms, 포착 ±170.5ms. 뗌은 딱 ±85.5 / 아슬 ±160.5.
- 헛누름: 1회 0.5점 감점, 상한 없음 (일정 간격 연타 꼼수 차단용. 기획서의 0.2점·10% 상한은 폐기됨).
- 등급 (`GRADE_CUT`): 만선 80 이상, 그럭저럭 60 이상, 그 아래 다시 출항.
- 완벽 도전: 헛누름 2회까지 허용, 3회째 실패. 무지개 도장은 그럭저럭 이상일 때만.
- 첫 실행 때 박자 보정 화면(8번 탭, 양 끝 제외 평균)을 권한다. 보정값은 판정에만 적용되고 그림에는 적용하지 않는다.

## 2. 코드 구조 (rhythm.html)

- 맨 위 상수: `CFG`(판정 창), `GAMES`(곡 목록·BPM·마디 수), `GRADE_CUT`, `SKEY`(저장 키).
- 채보: `SUSHI_RAW`, `SALUTE_RAW`+`PAT`, `PUFFER_RAW`, `GULL_STR`, `RMX_SEG` → `buildChart(id)` 가 노트 배열로 만든다. 곡별 기대 개수는 `EXPECT` 에 있어 채보를 바꾸면 같이 맞춘다.
- 연습: `PRACTICE` 표 (단계 3~4개, 과녁에 맞춘 음 3번 성공이면 통과, 한 단계 4번 돌면 자동 진행, 건너뛰기 버튼 처음부터 표시).
- 오디오: 자체 `AudioContext`(`AU`), `auChain`(반주만 압축 → 덕킹 → 리미터, 신호·효과음은 압축 없이 리미터로), 악기 정의 `I`, 곡 편곡 `SONG` 과 `*Groove` 함수들, 곡별 음량 배율 `MIX`, 플레이어 소리 `PLAYER_K`. 25ms `setInterval` 로 0.1초 앞을 미리 예약(`tick`), 그리기는 `requestAnimationFrame`(`frame` → `render`).
- 시계: 곡 시각 = 오디오 시각 − 시작 시각. 입력은 `event.timeStamp` 를 `heardAt()`(getOutputTimestamp 기준 "들리는 시각")으로 바꿔 판정. 시뮬 시계(`clock('sim')`)는 결정적이라 봇 검증에 쓴다.
- 화면: 논리 월드 가로 1280×720 / 세로 720×1280, contain 배치, 픽셀 밀도 최대 2배(`resize`). 모든 게임에 과녁(`drawTarget`)과 일정 속도로 줄어드는 링이 있고 링이 과녁에 닿는 순간이 정답 시각이다.
- 버튼 최소 크기: `button()` 앞 `MIN_BTN` 규칙 (화면 배율이 작으면 누름 영역을 키움).
- 검증 API `window.rhythm`: `games()`, `chart(id)`, `start(id, {sim, force, practice, perfect})`, `clock('sim'|'real')`, `advance(sec)`, `input('bot', 'down'|'up', 곡시각)`, `state()`, `result()`, `offset(ms)`, `view()`, `reset()`, `skip()`, `pause()`, `resume()`, `schedLog()`, `stamps()`.
  - 예: `rhythm.start('sushi', {sim:true, force:true}); const c = rhythm.chart('sushi'); c.notes.forEach(n => rhythm.input('bot','down', n.t)); rhythm.advance(c.lengthSec + 2); rhythm.result()` → 100점.

### 원인과 결과 (수정 전 → 후, 봇·렌더 실측)

- 3번 원인: 실전에 링이 없었고(연습에만 있었음), 초밥은 밥·'톡'이 정답 1박 전 신호 순간에만 움직이고 정답 순간엔 변화가 없었음. 따라해 막대는 칸 왼쪽 끝 기준이라 점 가운데 도달이 정답보다 +134ms 늦었음. 끼룩단은 반 박 먼저 착지.
  - 후: 링이 과녁에 닿는 시각 − 정답 시각 = 5곡 314건 평균 0ms, 최대 0ms (따라해 막대 최대 1ms).
- 1·2번 원인: 곡 에너지 95~99%가 킥·베이스·튜바, 150Hz 아래 비중 52~74%, 신호 소리가 반주보다 6~15dB 작았고 반주와 신호가 압축기를 같이 써서 킥마다 신호가 눌렸음.
  - 후: 150Hz 아래 비중 3~16%, 2kHz 위 15~33%, 신호가 반주보다 +6~+20dB, 4분 박 온셋 96~100%.
- 4번: 초보 흉내 봇(치우침 +25ms, 흔들림 σ60ms, 10% 놓침, 헛누름 3회)이 60점 넘는 시드 — 초밥 6/10·따라해 3/10 → 10/10·10/10. 보통 봇 첫 두 곡 약 90점, 능숙 봇 전곡 97~99점. 꼼수(무입력·무작위 연타·일정 연타)는 계속 0~53점.

## 4. 검증 기준 (다음 수정 때도 이대로 확인)

도구는 `tools/rhythm/` 에 있다. 모두 로컬 정적 서버(저장소 폴더를 :8766 으로 서빙)와 원격 디버깅 포트가 열린 크롬(기본 `localhost:9224`)을 쓴다.

| 항목 | 도구 | 기대값 |
|---|---|---|
| 판정 기본 | `smoke.js` | 5곡 완벽 봇 100점 만선, 무입력 최저, 페이지 오류 0, 폰 가로 스크롤 없음 |
| 사람 흉내 난이도 | `bots.js` | 초보가 초밥·따라해에서 70% 이상 시드 60점+, 보통 전곡 60점+, 능숙 전곡 만선, 꼼수 최저 |
| 화면 정렬 | `align.js`, `pix.js`, `shots.js`, `mob.js` | 링이 과녁에 닿는 시각 − 정답 시각 평균 ≤10ms, 최대 ≤17ms |
| 음악 | `spec.js` (+`page-lib2.js`) | 150Hz 아래 ≤25%, 2kHz 위 ≥15%, 4분 박 온셋 ≥90%, 신호 ≥ 반주 +3dB, 클리핑 0 |
| 허브·폰 흐름 | `flow-hub.js`, `flow-real-audio.js` | 아이폰13 세로·844×390 가로·1920×1080 에서 허브→보정→5곡 연습·본게임·결과, 40px 미만 버튼 0, 실제 오디오 모드 늦은 예약 0 |
| 성능 | `perf.js` | 한 프레임 그리기 중앙값 1ms 안팎(측정값 0.2~0.3ms), 메모리 증가 없음 |

주의
- 소리는 헤드리스 크롬에서 귀로 들을 수 없다. 음악은 오프라인 렌더 수치로만 확인했으니 사람이 직접 들어 봐야 한다.
- 공용 헤드리스 크롬에 다른 작업 탭이 많으면 프레임 측정이 크게 흔들린다(빈 페이지도 초당 1~5프레임까지 떨어진 적 있음). 성능은 그리기 비용(render 호출 시간)으로 판단한다.
- 여러 스크립트를 동시에 돌릴 때는 서로 다른 루프백 주소(127.0.0.x)로 열어 localStorage 를 분리한다.

## 5. 남은 과제 (검수에서 나온 것, 아직 안 고침)

- 카운트인 딸깍이 다른 신호보다 약함 (반주 대비 최저 −3.3dB, 따라해·끼룩단). 딸깍을 키우거나 카운트인 마디의 킥을 줄이는 방안.
- 전체 음량이 개편 전보다 2.6~8.1dB 작음 (초밥이 가장 작음 −27.3dBFS, 피크 0.93이라 여유 있음). 마스터 +2~3dB 검토.
- 따라해 반주만 떼면 150Hz 아래가 약 40% (짧은 베이스라 믹스 전체로는 9%). 참고.
- 복어: 다음 음으로 넘어갈 때 몸 크기가 한 프레임에 19px 바뀌는 순간이 있음 (판정·정렬에는 영향 없음).
- 끼룩단 고역 비율 15.1%, 정답타 대 반주 최저 +0.7dB 로 목표 경계. 반주를 더 두껍게 하면 무너질 수 있음.
- 폰 세로에서 허브의 ☰ 메뉴 버튼이 게임 왼쪽 위 숫자를 가림 (허브 쪽, 원래 있던 문제. 배치는 사용자가 결정).
- 한 번, 공용 헤드리스에서 대축제 도중 입력이 먹지 않은 적 있음. 창 포커스를 잃으면 일시정지되는 설계 동작으로 보이며 재현 안 됨.

## 6. 배포 방법

작업 폴더에 다른 작업의 미커밋 변경이 섞여 있을 수 있으므로, 원격 최신본 기준 별도 worktree 에서 이 게임 파일만 올린다.

```bash
git fetch origin
git worktree add --detach ../chamchicode-deploy origin/main     # 이미 있으면: git -C ../chamchicode-deploy checkout --detach origin/main
cp rhythm.html ../chamchicode-deploy/rhythm.html
cd ../chamchicode-deploy && git add rhythm.html && git commit -m "..." && git push origin HEAD:main
```

- push 인증: 로그인 창이 뜨면 저장소 주인 계정으로 로그인. 비대화형 셸에서는 `GCM_INTERACTIVE=always` 와 `git -c credential.interactive=always push ...` 로 로그인 창을 띄울 수 있다.
- 배포 확인: `gh api repos/bogeun35/chamchicode/pages/builds/latest` 가 `built` + 새 커밋이 되면, 실제 사이트 파일 크기가 올린 파일과 같은지 비교한다.
- 허브(`index.html`)를 건드릴 때는 기존 항목을 바꾸지 말고 추가만 한다. 메뉴 묶음은 `NAV_GROUPS`, 콘솔 연결 목록은 `['tuna', 'rock', 'mine', 'shelldiver', 'rhythm']`.
