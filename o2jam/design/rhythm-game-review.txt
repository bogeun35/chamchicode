참치코드 리듬게임 — 재미와 타격감 검토 (2026-10-03)
검토: 게임 디자인 / 음악 기획 / 개발. 현재 소스 기준, 이번 검토에서 실제 청취·다중 브라우저 플레이 검증은 수행하지 않음.

방향: 음악에 맞는 행동 → 즉시 보이는 접촉 → 성공 누적 → 곡 절정의 보상 → 기록 변화 → 다음 도전.
효과의 양보다 각 반응의 이유와 시간적 일치가 중요하다. 재미는 실제 플레이 평가로 검증해야 한다.

즉시 반영
- 콤보는 레인 안, 평상시 50% 투명도와 성공 직후 110ms 강조. 숫자 크기를 제한.
- 노트 렌더링을 떠오르는 피드백 위로 이동하여 실제 채보를 가리지 않음.
- 판정 700ms→380ms, 크기 32→26px. 반복 성공을 짧게 구분.
- 콤보 기념 문구는 상단, 50콤보 연출은 중앙 FEVER 문구 대신 외곽 금색 프레임.
- 큰 발광의 사각 잘림 수정, 타격 순간 강도·색 고정.

우선순위 1: 음악과 입력
- 자동 채보 대표 8마디씩 청취/플레이하며 킥·주선율과 노트 관계 확인.
- 쉬움은 주요 박자, 보통은 주선율, 어려움은 세부 리듬. 반복 구간은 일관된 손동작.
- 동시타의 동일 클릭 중첩을 한 번의 음향 임팩트로 묶고 레인별 시각 반응 유지.
- 롱노트 시작/유지/끝의 시청각 반응 구분. 자동 끝의 일반 클릭 재생 제거 검토.
- EARLY/LATE 또는 짧은 오차 막대로 타이밍 교정. 오디오 보정 UX 확인.

우선순위 2: 기대와 절정
- 실제 곡 구간 정보를 수작업 표기해 전주/벌스/후렴/드롭에 배경 에너지 차등.
- 연속 성공 연출과 JAM 점수 배율의 의미를 명확히 분리/안내.
- COOL은 짧은 선명한 코어, GOOD은 절제된 링, MISS는 복구 안내. 실패를 큰 효과로 보상하지 않음.
- 연타 구간 파티클 강도와 수량 상한, 게임 시간/음악은 흔들거나 멈추지 않음.

우선순위 3: 결과와 재도전
- 성취 배지 → 정확도/기록 차이 → 가까운 다음 목표 → 다시하기 순서.
- 총점보다 최고기록 차이와 달성 가능한 작은 목표 강조. 곡 중간 회복감을 유지.
- 난이도 별은 밀도만이 아니라 동시타/반복/롱노트 부담 포함. 실제 플레이 평가 병행.

싱글/멀티/화면 크기
- 내 레인의 피드백은 공통. 싱글 오른쪽은 곡/목표, 멀티 오른쪽은 상대 미니 레인.
- 현재 멀티는 점수 카드이며 상대 노트/키 입력 화면은 아직 미구현.
- 동일 채보와 공통 시간으로 상대 노트를 렌더하고 실제 입력·판정 이벤트로 효과 표시.
- 250ms 통계 송신만으로 실제 타격을 재현할 수 없음. 이벤트 순번/시각/키 상태/판정 정보와 지연 처리 필요.
- 늦은 진입은 과거 노트를 MISS로 계산하지 않도록 정책/필터 수정. 음원 길이 불일치 대응.
- 좁은 화면에서 1280x720 일괄 축소 대신 레인 우선 배치와 접히는 보조 HUD 필요.

성능과 검증
- 정적 배경/레인 캐시, 메뉴 렌더 빈도 제한은 장치 측정 후 적용.
- 판정/콤보/음향 동작 및 스크립트 구문 검사 통과. 실제 프레임 성능과 시청각 만족도는 미검증.
- 다음 평가: 쉬움/보통/어려움 각 30초, 빠른 동시타/롱노트/실패 복구/후렴, 2인 동시 플레이, 좁은 화면.
